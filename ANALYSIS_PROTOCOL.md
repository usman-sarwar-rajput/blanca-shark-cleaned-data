# Blanca single-shark exploratory analysis

Recorded before computing depth outcomes on 16 September 2026. This is a retrospective, exploratory protocol, not a public preregistration. Candidate selection was informed by the completed archive feasibility audit.

Animal: juvenile white shark 14_07, recovered PAT 14_07-132980, archive DOI 10.24431/rw1k6c3. Reference fixed by the previous tighter-time cyclone screen: 2015-06-08 12:00 UTC. Modelled locations and storm centre proximity do not establish exposure.

1. Preserve the original ZIP and previous outputs. Read the recovered out-Archive.csv directly. Check timestamps, duplicate records, deployment boundaries, depth offsets, gaps and temperature. Do not substitute nested archives or post-detachment Argos positions. Use original UTC timestamps; investigate any recorded time correction metadata.
2. Environmental matching: retrieve hourly ERA5 wind and mean sea-level pressure through Open-Meteo, using sea-cell selection; retrieve 2015 PacIOOS WW3 wave-height fields preserved by NOAA AOML. Retain source bytes, URLs, hashes, metadata and failures. Match hourly observations to the nearest available modelled shark position within six hours; retain matching lag and grid location. Do not interpolate shark positions. Inspect supplied GPE3 NetCDF for uncertainty information. A fixed +/-0.5-degree geographic sensitivity is only a scenario envelope, never a confidence region.
3. For environmental context use May 1–June 20, 2015 where accessible. An operational severe-condition screen is wind >=17.5 m/s OR significant wave height >=4 m sustained for three consecutive hours, within June 5–10. These investigator-defined screening rules are not a validated shark-response threshold. Missing weather cannot count as below threshold. Record onset at first of three qualifying hours, independently of depth. Inspect wind/wave sensitivity and spatial scenarios. If this gate is unconfirmed, retain the fixed audit reference and label analysis as change around that reference, not before local storm onset. If a model-based onset exists, report a second explicitly exploratory analysis; apply multiplicity adjustment across both reference families together.
4. Primary endpoint: hourly median raw depth (metres). Secondary endpoints: hourly depth interquartile range (metres) and mean absolute vertical rate between consecutive one-minute median depths (m/min). The last is a sensor-derived movement proxy, not horizontal speed or direct swimming effort. One-minute values require >=3 samples; differences require exactly 60 seconds. Do not bridge gaps. Hourly depth requires >=180 of 240 expected 15-second records and hourly movement >=45 valid minute pairs. Near-surface fraction <=5 m and in-situ temperature are descriptive only; temperature changes with occupied depth and is not independent SST.
5. Main comparisons: baseline [-336,-72) hours, guard [-72,-48), pre48_24 [-48,-24), pre24 [-24,0), post24 [0,24). Fit OLS to the continuous hourly series [-336,+24), with UTC hour-of-day fixed effects, linear time trend, and indicators for guard and the three comparison periods. Baseline is the reference. Preserve spacing for serial-correlation inference; stop model if required hours are missing. Main uncertainty: Newey–West HAC lag 24, finite-sample correction, asymptotic normal 95% intervals. These are model-conditional intervals, not independent-animal confidence intervals. Holm adjustment across the 9 endpoint/comparison tests, or 18 if a second environmental reference is analysed. Guard is a nuisance term, not a tested discovery.
6. Sensitivities: HAC lags 12/48, no linear trend, negative depths clipped to zero, and five-minute instead of one-minute movement proxy (>=15 samples per bin, >=9 valid within-hour pairs). Report all, never select whichever gives significance. Constant depth offset leaves depth changes and IQR largely unchanged; variable drift remains a limitation. Do not infer precise dive counts without a separately justified dive definition.
7. Ordinary variation: descriptive pseudo-reference comparisons, same UTC hour, every day from April 16–July 15 with complete baseline and comparison windows. Exclude any pseudo-reference whose entire [-14,+1) day window intersects June 1–12. They are contextual periods, not certified non-storm controls. Match each comparison hour to baseline UTC-hour means; calculate median-depth differences and empirical absolute-effect ranks. Overlapping pseudo-windows are dependent; ranks are not p-values or independent replications.
8. Deliver reproducible code, quality results, source attribution, effect tables, plots and a readable report. Distinguish any change, association with modelled local conditions, and evidence of anticipation. One shark and one selected cyclone cannot establish repeatability, forecasting skill or mental awareness.

Quality clarification before outcome estimation: source event/annotation rows repeat timestamps but have missing depth. Exclude nonfinite depth rows first, remove exactly identical time/depth/temperature rows, then require unique measurement timestamps. One identical finite duplicate was found at 3 August 2015 20:00 UTC, outside the conservative deployment interior. No contradictory finite depths were found. Do not average annotations into sensor measurements.

Implementation record (added after running the analysis; not a prospective amendment): model weather sites use ERA5 sea-cell preference. The WW3 nearest persistently wet cell is selected using >=90% nonmissing wave values over the requested interval; matches >100 km are treated as unavailable. Main-event maximum offsets were 37.4 km (ERA5) and 44.3 km (WW3). The GPE3 grid itself was inspected and its nonnegative mass normalized; its concentrated cell weights were not treated as calibrated real-world confidence bounds. No severe-condition onset was identified, so only the original reference was tested (nine comparisons). Visual review flagged a June 9 21:00 wave-source discontinuity after the tested post-reference interval; original values were retained with the flag. This record documents retrospective implementation details transparently.
